# CodeStart на Render

Подготовлен Blueprint `render.yaml`: один web service `0.5c-512mb`, постоянный диск 1 GB, Python 3.14.10, один процесс Gunicorn с четырьмя потоками и WhiteNoise для статики. Создание платного сервиса пока не выполнялось.

По опубликованным тарифам на 28 октября 2026 ориентир составляет **$7.25 в месяц**: $7 за сервис и $0.25 за диск 1 GB. Налоги, превышение включённых лимитов, домен, SMTP и использование OpenAI сюда не входят. Окончательную сумму проверьте на экране Render перед созданием сервиса: https://render.com/pricing.

## Подготовка аккаунта

1. Загрузите исходный код в приватный Git-репозиторий. Не загружайте `.env`, `db.sqlite3`, резервные копии и `venv/`.
2. В Render подключите репозиторий через Blueprint. До подтверждения создания проверьте сервис и диск из `render.yaml` и стоимость.
3. Для `DJANGO_SECRET_KEY` задайте случайный секрет минимум 50 символов. Генерация на своём компьютере: `python -c "import secrets; print(secrets.token_urlsafe(64))"`. Не присылайте результат в чат. Автогенерация секрета в Blueprint намеренно не используется: стандартная длина Render короче установленного в проекте минимума.
4. Основной `.onrender.com` hostname берётся из `RENDER_EXTERNAL_HOSTNAME`. Для своего домена задайте в панели `DJANGO_ALLOWED_HOSTS` (основной и дополнительный домены через запятую), при необходимости `DJANGO_CSRF_TRUSTED_ORIGINS` с полными HTTPS-адресами.
5. Для доставки писем добавьте SMTP-параметры из `.env.example`. Без них письма остаются в консоли; доставка пользователям не работает. Для AI отдельно добавьте ключ и выбранную модель.

## Как выполняется запуск

Сборка устанавливает `requirements-render.txt` и собирает статику. Миграции на этапе сборки или pre-deploy не выполняются: постоянный диск там недоступен.

При запуске `python -m deploy.render_start` подключённая база из `/var/data/db.sqlite3` сначала копируется в `/var/data/backups/` (если уже существует). При неуспешной копии или миграции запуск останавливается. Затем выполняются миграции и запускается Gunicorn на порту Render. На первом запуске создаётся новая база с учебными материалами; локальные аккаунты автоматически не переносятся.

При повторных запусках резервные копии накапливаются: регулярно скачивайте нужные копии вне Render и освобождайте место после проверки сохранности. Копия на том же диске не заменяет внешнее резервное хранение.

## Проверка размещения

Откройте HTTPS-адрес `/health/`, затем главную, вход и страницу урока. Проверьте стили и отсутствие циклических HTTPS-перенаправлений. Конфигурация `config.render_settings` доверяет заголовку схемы только в среде за proxy Render; локальный запуск использует обычный `config.settings`.

В Shell сервиса создайте администратора: `python manage.py createsuperuser`. Затем проверьте реальную доставку писем и, если настроен AI, согласованный запрос к провайдеру. Проверьте сохранение данных после перезапуска сервиса.

Миграции, запуск Gunicorn и монтирование диска на Linux Render требуют проверки на самом хостинге. Локальная Windows-проверка не подтверждает фактическую публикацию.

Основание конфигурации: https://render.com/docs/blueprint-spec, https://render.com/docs/disks, https://render.com/docs/deploy-django.

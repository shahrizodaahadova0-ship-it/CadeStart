# CodeStart — состояние проекта на 30 октября 2026

Актуальный вариант размещения изменён по выбору пользователя: **Render Free + внешняя PostgreSQL**. Основной `render.yaml` больше не создаёт платный сервис или диск; платная конфигурация сохранена в `render-paid.yaml`. Инструкция заполнения формы находится в `deploy/RENDER-FREE.md`. Новая конфигурация, запуск без локального диска и смежные сценарии проверены 14 целевыми тестами. Подключение к реальной PostgreSQL и публикация пока не проверены: требуется создать внешнюю базу и добавить её секретный `DATABASE_URL` в Render.

Локальная версия реализована и доступна по адресу http://127.0.0.1:8000/. Это учебная платформа с ручной проверкой решений; код ученика сервер не исполняет.

## Реализовано

- Регистрация, вход с возвратом к запрошенной странице, восстановление и смена пароля, подтверждение email, профиль и часовой пояс.
- Русский и узбекский интерфейс, учебная диагностика с сохранением незавершённых ответов.
- Восемь уроков, заметки, самопроверки, отметки изучения и повторение без потери заметок.
- Виртуальная компания, пять практических заданий, Kanban, черновики и история отправок.
- Назначение ревьюера, проверка, доработка, оценка, закрытое обсуждение и уведомления.
- Согласование изменения требований, редактирование учебных материалов и история редакций с восстановлением.
- Результаты по последней попытке каждой задачи, отчёты JSON/Markdown с историей, требованиями и самопроверками.
- Адаптивные стили, прокрутка длинного меню, управление меню с клавиатуры и предупреждение о несохранённых формах.
- Серверная интеграция AI с отдельными приватными диалогами, согласием на отправку и обработкой ошибок; без настроек доступна встроенная справка.
- Адрес `/health/` для мониторинга Django и базы, с некешируемым ответом 200/503 без технических подробностей. Подготовлена инструкция размещения `DEPLOYMENT.md`.
- Чтение локального `.env`, проверка конфигурации сервисов, production-настройки, страницы ошибок и резервное копирование SQLite.

## Итоговые проверки

Полный прогон `manage.py test`: **106 тестов прошли**, ошибок системной проверки Django нет. Главная, вход, регистрация, восстановление пароля и статические файлы дополнительно проверены HTTP-запросами к обновлённому локальному серверу: ответ 200.

После добавления мониторинга отдельно прошли 7 тестов проверки состояния и страниц ошибок. Полный прогон из 106 тестов относится к состоянию перед добавлением трёх тестов мониторинга.

Подготовлены файлы Render: `render.yaml`, отдельные настройки, зависимости, сборка и запуск с базой и копиями на постоянном диске. Прошли 10 целевых тестов запуска/копирования/мониторинга. Дополнительно на временной базе проверены production-миграции, HTTPS-заголовок proxy, `/health/`, отдача CSS через WhiteNoise и сохранение резервной копии. Gunicorn под Linux и фактическое размещение на Render ещё не проверены. Инструкция и ориентир стоимости находятся в `deploy/RENDER.md`.

Сквозные тесты на RU и UZ проверяют регистрацию, диагностику, завершение всех уроков и самопроверок, черновик, отправку, доработку, повторную отправку, принятие ревьюером, уведомление и экспорт отчёта. Все данные этих тестов создаются в отдельной тестовой базе.

Дополнительно выполнены:

- проверка синтаксиса JavaScript и 10 проверок взаимодействия меню в имитации DOM;
- проверка актуальности миграций и сборка статических файлов;
- проверка совместимости установленных Python-зависимостей;
- создание и проверка целостности резервной копии базы;
- генерация локальных HTML для последующей визуальной проверки в `artifacts/` без изменения данных приложения.

Проверка `check --deploy` с временными production-параметрами проходит без ошибок и оставляет предупреждения W005/W021: HSTS для всех поддоменов и preload выключены. Эти опции требуют решения владельца после настройки реального домена и HTTPS. Временные параметры не записывались в рабочий `.env`; подключений к внешним сервисам эта проверка не выполняет.

## Что ещё нужно для публичного запуска

1. Настроить `OPENAI_API_KEY` и `OPENAI_MODEL`, затем проверить реальный ответ провайдера. Платные запросы в ходе разработки не выполнялись; API проверен имитациями.
2. Настроить SMTP и адрес отправителя, проверить доставку восстановления пароля и подтверждения email. Сейчас письма выводятся в консоль сервера.
3. Создать сервис Render по подготовленному Blueprint из Git-репозитория, настроить секреты и проверить размещение. Собственный домен необязателен: сначала можно использовать адрес Render. Публикация пока не выполнялась; `runserver` используется для локального просмотра.
4. Проверить внешний вид в реальном браузере на телефоне и компьютере. Выполненные тесты шаблонов, CSS по коду и имитация DOM не заменяют визуальную проверку.

Инструкции запуска, параметры окружения, ограничения и команды резервного копирования находятся в `README.md` и `.env.example`. Секреты не следует отправлять в чат или сохранять в репозитории.

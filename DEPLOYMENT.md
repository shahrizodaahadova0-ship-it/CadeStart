# Размещение CodeStart

Для выбранного варианта Render подготовлены `render.yaml` и [пошаговая инструкция](deploy/RENDER.md). Настройки Render отделены от локальных; база и копии размещаются на постоянном диске.

Приложение готово к дальнейшей настройке на выбранном хостинге. Само размещение ещё не выполнено. Команды ниже запускаются из корня проекта в его Python-окружении; в Windows используйте `venv\Scripts\python.exe` вместо `python`.

## Что подключить на хостинге

- Python подходящей версии для зависимости из `requirements.txt` и постоянный WSGI-процесс с точкой входа `config.wsgi:application`. Конкретный сервер и способ автозапуска зависят от хостинга.
- Домен с HTTPS. Запросы направляются к WSGI-приложению, а `/static/` обслуживается из каталога `staticfiles/`.
- Постоянное хранилище для `db.sqlite3` и приватных резервных копий. При обновлении кода базу нельзя заменять файлом из нового релиза. На платформе с временной файловой системой SQLite в каталоге приложения использовать нельзя без постоянного диска.
- Параметры окружения процесса либо приватный `.env`. Образец находится в `.env.example`; рабочие секреты туда не записываются.

## Параметры

Установите `DJANGO_DEBUG=false`, новый случайный `DJANGO_SECRET_KEY` длиной минимум 50 символов и конкретные домены в `DJANGO_ALLOWED_HOSTS`. Для генерации секрета на сервере можно выполнить `python -c "import secrets; print(secrets.token_urlsafe(64))"` и сохранить результат приватно.

При необходимости задайте полные HTTPS-адреса в `DJANGO_CSRF_TRUSTED_ORIGINS`. SMTP настраивается переменными `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_TLS`, `SMTP_SSL`, `DEFAULT_FROM_EMAIL`. Для AI нужны `OPENAI_API_KEY` и `OPENAI_MODEL`.

Приложение при выключенном DEBUG перенаправляет HTTP на HTTPS. Если TLS завершается на reverse proxy, настройку доверия к proxy-заголовку нужно согласовать с конфигурацией конкретного хостинга; иначе возможно циклическое перенаправление. Автоматическое доверие к произвольному `X-Forwarded-Proto` не включено.

## Подготовка и обновление

Перед изменением существующей базы создайте копию:

```text
python manage.py backup_database
```

На первом запуске, когда базы ещё нет, сначала выполните миграции. После установки зависимостей и настройки окружения выполните:

```text
python manage.py migrate
python manage.py collectstatic --noinput
python manage.py check --deploy
python manage.py service_status
```

`service_status` проверяет наличие конфигурации, но не доступность провайдера. `check --deploy` в локальном режиме сообщает об отладочных настройках и консольной почте. В production остаются предупреждения W005/W021, пока не включены HSTS для всех поддоменов и preload; включать их следует после проверки HTTPS на всём домене.

Затем запустите или перезапустите WSGI-процесс средствами выбранного хостинга. Для нескольких процессов потребуется общий кеш: сейчас ограничение частоты запросов AI использует память одного процесса. Для первого размещения нельзя предполагать, что этот лимит общий для нескольких работников.

## Проверка после запуска

Проверяйте `https://ваш-домен/health/` без пользовательских cookies. Ответ `200 {"status":"ok"}` подтверждает обработку запроса Django и простой запрос к базе. При ошибке базы возвращается `503 {"status":"unavailable"}` без технических подробностей. Ответы не кешируются; поддерживаются GET и HEAD. Проверка не подтверждает актуальность миграций, доставку почты, AI, наличие статики или возможность записи на диск.

Откройте главную, вход, учебный путь и задание на телефоне и компьютере; проверьте статику. Через тестовый аккаунт проверьте доставку подтверждения email и восстановления пароля. При включении AI выполните согласованный реальный запрос в аккаунте владельца сервиса. Проверьте создание резервной копии на постоянном диске и доступ к ней вне жизненного цикла релиза.

Все дальнейшие команды хостинга, адреса и настройки proxy следует конкретизировать после выбора площадки. Текущий локальный сервер на `127.0.0.1:8000` предназначен для просмотра на компьютере.

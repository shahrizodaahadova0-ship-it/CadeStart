# CodeStart

Текущее состояние, итоговые проверки и оставшиеся шаги публичного запуска: [PROJECT_STATUS.md](PROJECT_STATUS.md).

Порядок размещения и проверки состояния приложения: [DEPLOYMENT.md](DEPLOYMENT.md). Адрес `/health/` доступен монитору без входа: проверяет Django и простой запрос к базе, возвращает 200 или 503 без технических подробностей.

Отметку «Урок изучен» можно снять кнопкой «Вернуться к повторению». Это не удаляет заметки и результаты самопроверки; общий прогресс пересчитывается.

Заметки урока ограничены 20 000 символами. При превышении лимита сервер показывает ошибку и оставляет введённый текст в редакторе: сохранённые заметки и отметка изучения не меняются, текст не обрезается.

Изменения уроков и заданий через админ-панель сохраняются в истории редакций: автор, время, список изменённых полей и полные снимки до/после. Для заданий также сохраняются номера версий. История доступна через `/content/` и Django admin только сотрудникам с правом просмотра или изменения соответствующих материалов; изменять и удалять записи через админ-панель нельзя. Сохранение без содержательных изменений запись не добавляет. Прямые изменения через ORM или SQL этим журналом не отслеживаются.

Из записи истории можно восстановить текст, предшествовавший этому изменению. Доступно только пользователям с правом изменения материала, после отдельного подтверждения. Подтверждение действует 15 минут и связано с текущей датой изменения: если материал уже отредактирован, восстановление блокируется до повторного просмотра. При восстановлении прежний текущий текст сохраняется новой записью истории; для задания создаётся очередная версия, старые отправки не меняются.

Навигация учитывает роль: ученик видит учебные разделы, ревьюер — свои проверки и материалы, а административные ссылки и кнопки редактирования показываются только при наличии прав на соответствующую модель. Эти ограничения дополнительно проверяются сервером Django admin, скрытие кнопок не заменяет проверку доступа.

Практические задания редактируются в `/admin/projects/taskcontent/`: названия и описания RU/UZ, критерии приёмки (по одному на строку), технология и приоритет. Критерии должны иметь одинаковое количество пунктов в обоих языках. Каждое содержательное изменение увеличивает версию задания; повторное сохранение без изменений — нет. Отправка сохраняет серверный снимок требований. Если версия формы устарела, данные формы остаются на странице, а отправка блокируется до проверки текущих критериев. Черновики сохраняются независимо от смены версии. Старые отправки при миграции привязаны к исходной версии из каталога.

Уроки включают самопроверку на основе вопросов по теме. Ответы проверяются сервером, объяснения и последний результат сохраняются в аккаунте. Самопроверка не выполняет код и не меняет ручную отметку изучения; сохранённые заметки при проверке остаются на месте. Для каждого урока используется отдельный результат.

Результаты самопроверок отдельно показаны на странице результатов и в отчёте, включая экспорт JSON и Markdown. Между уроками есть последовательные переходы; последний ведёт к практическим задачам. При уходе с несохранёнными изменениями редактора браузер предупреждает о возможной потере текста.

Предупреждение также защищает несохранённую форму решения: ссылку, SHA, описание и чек-лист. Если вернуть поля к исходным значениям, предупреждение снимается. Сохранение черновика и отправка формы проходят без лишнего предупреждения; сами данные сохраняются только после успешного ответа сервера.

При назначении активного staff-ревьюера через админ-панель ему приходит уведомление. Собственную работу назначить себе нельзя. Результаты проверки, изменённые администратором, уведомляют ученика; одинаковое сохранение не дублирует сообщения. Оригинальный код, ссылка и описание ученика в этой форме доступны только для чтения. В `/content/` администраторы с соответствующими правами видят очереди без ревьюера и на согласование; обычным ревьюерам общие счётчики не раскрываются.

В результатах и отчёте сводка строится по последней отправке каждой задачи; повторные попытки не увеличивают число принятых задач. На странице результатов доступны история всех попыток, фильтр статусов и страницы по 10 записей. JSON и Markdown включают как последние версии, так и полную историю с датой, номером отправки и коммитом. Сохранение черновика новой задачи переводит её в колонку «В работе»; после отправки приоритет имеет статус проверки последней версии.

Предложения по изменению требований рассматриваются в `/admin/projects/changeproposal/`. Администратор с правом изменения предложений выбирает решение и оставляет обязательный комментарий. Сохраняются автор и время решения, ученик получает уведомление и видит ответ в сценарии. Исходную оценку ученика администратор через эту форму не редактирует. Повторное сохранение без изменений не создаёт новое уведомление.

После регистрации пользователь сразу переходит к выбору уровня и недельного времени обучения. Учебный путь доступен независимо от настройки внешних сервисов.

Вход сохраняет адрес запрошенной страницы после ошибки пароля и возвращает к ней после успешной попытки. Уже вошедший пользователь также переходит по безопасному адресу `next`; при его отсутствии открывается кабинет. Внешние адреса отклоняются. Сообщение о неверных данных доступно на русском и узбекском; неактивные аккаунты войти не могут.

У отправленного решения есть закрытое обсуждение: ученик и назначенный staff-ревьюер могут оставлять пояснения и вопросы. Новый комментарий уведомляет второго участника; комментарии не меняют оценку и статус. Другие пользователи, включая неназначенных staff, не получают доступ к обсуждению.

Решение задания можно сохранить как черновик: ссылка, SHA и описание допускают незавершённый ввод. Черновик доступен только своему пользователю, загружается при повторном открытии формы и отмечается на Kanban-доске. Сохранение черновика не отправляет решение и не создаёт уведомления. Для окончательной отправки действуют полная валидация и обязательный чек-лист; после успеха удаляется только черновик этой задачи.

Панель ревьюера поддерживает поиск, фильтр статусов и счётчики назначенных решений. Для возврата на доработку обязателен комментарий; повторное сохранение без изменений не создаёт уведомления.

Уведомления поддерживают индивидуальную отметку прочтения и переход к результату с одновременным прочтением. Счётчик в верхнем меню учитывает только непрочитанные сообщения текущего пользователя. Список разбит на страницы по 15 сообщений; фильтр непрочитанных сохраняется при переходе между страницами.

Учебная платформа на Django. Интерфейс основан на предоставленных макетах: тёмно-синяя и тёмно-зелёная тема, адаптация для телефона, русский и узбекский интерфейс.

## Запуск в Windows

```powershell
.\venv\Scripts\python.exe manage.py migrate
.\venv\Scripts\python.exe manage.py runserver
```

Откройте http://127.0.0.1:8000/. Для нового окружения: `python -m venv venv`, затем `venv\Scripts\python.exe -m pip install -r requirements.txt`.

## Разделы

- `/` — главная и существующая библиотека проектов.
- `/register/`, `/login/`, `/password/reset/`, `/email/verify/` — аккаунт и восстановление доступа.
- `/onboarding/`, `/diagnostic/` — выбор опыта, времени и короткая диагностика.
- `/dashboard/`, `/learning/` — личный кабинет, уроки и сохранение черновиков.
- `/company/`, `/company/tasks/` — учебный проект интернет-магазина, Kanban, задания и отправки решений.
- `/company/documents/`, `/company/team/`, `/company/scenario/` — документы, роли команды и оценка изменения требований.
- `/mentor/`, `/manager/` — встроенная справка и состояние без подключённого AI.
- `/notifications/`, `/results/`, `/report/`, `/profile/` — уведомления, реальные результаты, экспорт JSON/Markdown и настройки.
- `/reviewer/`, `/content/` — разделы для staff-пользователей.
- `/states/` — справочник состояний интерфейса.

Прогресс уроков — самоотметка пользователя, не автоматическая оценка кода. Код в редакторе не выполняется на сервере. Доска задач формируется по последней отправке каждой задачи. Решения проверяет человек: создайте администратора через `manage.py createsuperuser`, откройте `/admin/projects/submission/`, назначьте staff-ревьюера в поле `reviewer`. Ревьюер увидит только свои назначения на `/reviewer/`; результат создаёт уведомление ученику.

Диагностика состоит из 12 вопросов. Кнопка «Сохранить и выйти» сохраняет выбранные ответы и номер вопроса в аккаунте; продолжить можно с другого устройства. Незавершённый тест не меняет предыдущий результат. После завершения показываются ответы по темам, а первая тема с ошибкой или пропуском становится рекомендованным уроком в кабинете. Пройденные уроки сохраняют свои отметки и пропускаются при выборе следующего шага. Если все ответы верны, предлагается закрепить знания тестированием.

Порядок курса, уровни, задания и вопросы самопроверки находятся в `projects/catalog.py`. Тексты восьми существующих уроков перенесены в базу отдельной миграцией и редактируются через `/admin/projects/lessoncontent/`; кнопки редактирования также есть в `/content/` для пользователей с правом изменения материалов. Доступны русская и узбекская версии, код, подсказки и длительность от 1 до 180 минут. Идентификатор урока защищён от изменения, чтобы сохранить связь с прогрессом и самопроверками. Изменения сразу видны ученикам после сохранения. Библиотека публичных проектов также редактируется в Django admin.

## Внешние сервисы

AI-ментор и AI-менеджер интегрированы с OpenAI [Responses API](https://developers.openai.com/api/docs/guides/text). Для включения задайте `OPENAI_API_KEY` и `OPENAI_MODEL` в окружении процесса. Модель выбирает владелец проекта из доступных его аккаунту; по умолчанию ни одна не задана. Без этих настроек работает встроенная справка. Платные запросы при разработке не выполнялись: тесты используют имитацию API.

Вопрос и последние 10 сообщений выбранного диалога отправляются в OpenAI после подтверждения в форме. Ответ сохраняется в локальной базе, история доступна только владельцу и разделена между ментором и менеджером. Для запросов используется `store=false`; это не обещание полного отсутствия обработки/хранения на стороне провайдера. AI не выполняет код и не меняет статусы или оценки. Встроен интервал 10 секунд между запросами пользователя; текущий кеш локален процессу. Для нескольких production-процессов следует подключить общий кеш. Таймаут API — 30 секунд. Ошибка провайдера не создаёт фиктивный ответ и оставляет вопрос в форме.

Письма по умолчанию выводятся в консоль сервера. Для доставки задайте `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `DEFAULT_FROM_EMAIL`; STARTTLS включён по умолчанию. Для SMTP-over-SSL задайте `SMTP_SSL=true` (типичный порт 465). Создайте локальный `.env` по примеру `.env.example` и перезапустите сервер: `.env` читается автоматически, а переменные окружения процесса имеют приоритет. Поддерживаются строки `KEY=value`, необязательное `export`, одинарные/двойные внешние кавычки и комментарии на отдельных строках. Значения читаются буквально, без запуска команд, подстановки переменных и многострочных значений. Символ `#` внутри значения сохраняется. Не присылайте ключи в чат и не коммитьте их в репозиторий. Ссылка подтверждения email действует 24 часа, повторная отправка ограничена одной минутой.

Проект настроен для локальной разработки (`DEBUG=True`). До публичного размещения необходимы отдельные production-настройки Django, секретный ключ из окружения и почтовый провайдер.

Параметры размещения: `DJANGO_DEBUG=false`, `DJANGO_SECRET_KEY` (отдельный секрет минимум 50 символов), `DJANGO_ALLOWED_HOSTS` (конкретные домены через запятую), при необходимости `DJANGO_CSRF_TRUSTED_ORIGINS` (полные HTTPS-адреса). При выключении DEBUG включаются HTTPS-перенаправление и secure cookies; настройте HTTPS на сервере. За reverse proxy отдельно проверьте схему запроса и доверие к proxy-заголовкам. Для статики выполните `manage.py collectstatic` и настройте её обслуживание из `staticfiles/`; `runserver` предназначен для разработки. Для production не допускаются отсутствующий секрет и wildcard в списке хостов.

Команда `manage.py service_status` показывает только режимы конфигурации (AI, почта, разработка/production), не печатает ключи и не выполняет платные запросы. Она не подтверждает доступность внешних сервисов.

## Резервное копирование

`manage.py backup_database` создаёт проверенную копию SQLite в `backups/` с уникальным именем. Используется SQLite Backup API, поэтому в копию попадают зафиксированные изменения, включая WAL. Существующий файл и рабочую базу команда не перезаписывает. Можно указать новый путь через `--output backups/manual.sqlite3`. Команда `manage.py verify_backup backups/manual.sqlite3` повторно проверяет целостность копии без изменения рабочей базы. Резервные копии содержат пользовательские данные и сеансы: каталог исключён из Git, храните его приватно. Восстановление рабочей базы автоматически не выполняется.

В production используются оформленные страницы 400, 403, 404 и 500 без технических подробностей. Страница 500 не зависит от запросов к базе через контекстные процессоры. Для устаревших CSRF-токенов показана инструкция повторного открытия формы. При `DEBUG=True` Django по-прежнему показывает отладочную страницу 404/500 разработчику.
